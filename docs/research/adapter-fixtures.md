## Honest gaps

- `tools-list-response.json` is a synthetic subset (14 entries), not the live 71-tool list. Capability discovery must assert schema/behavior against whatever the server returns; any fixture asserting an exact count would be wrong by construction.
- `_meta` key names for ETags (`kiwi.etag`) are fixture conventions; T04 must confirm the actual ETag carrier (text result vs `_meta`) against the live endpoint during the runner's capability pass and adjust the fixture before relying on it.
- The 16-hex truncation length for `msg_id` is a [P] default (`architecture.md` §2). The vectors were computed with real SHA-256 and must be recomputed if the default changes.
- The hash input framing is slash-joined `'{channel}/{from}/{opId}'`, not bare concatenation; bare concatenation is collision-prone (`channel="a/b", from="c"` ≡ `channel="a", from="b/c"`). `architecture.md` §2/§8 and PRD T16 still say `channel + from + opId`; T16 must align the wording (or implementation) to the slash-joined framing or the vectors are silently invalidated.
