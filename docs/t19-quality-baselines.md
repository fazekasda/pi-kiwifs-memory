# T19 quality and budget baselines (synthetic)

Task: T19 (PRD `tasks/prd-kiwifs-memory.md` AC 5/6). Everything in this
document is measured or asserted by `test/t19-budgets-quality.test.ts`
against the in-process fake MCP server (`test/fake-mcp-server.ts`) and a
scripted extraction stub. Machine-readable measured values:
`tasks/evidence/t19-budget-report.json` (regenerated by the test run).

## 1. What this evidence is — and is not

- **Synthetic only.** No live service, no network, no model calls. The
  extraction "model" is a deterministic stub returning scripted
  observations; the tokenizer is a local fixture.
- **The synthetic tokenizer is NOT production-compatible.** It is the
  word/punctuation fixture of `test/fixtures/t19-synthetic-tokenizer.mjs`
  (`synthetic-word-punct-v1 (NOT model-compatible; test fixture)`). It
  exercises the REAL cap-enforcement path (complete framed payload counted,
  lowest-ranked evidence dropped first, fail-closed on unreliable counts),
  but its absolute token counts say nothing about
  `z-ai/glm-5.3-flash` accounting. Production claims require a
  model-compatible tokenizer configured via `budgets.tokenizer` (§13 row 5);
  without one, automatic injection is visibly skipped — this remains the
  product behavior and is not relaxed here.
- **No production quality claim.** The QF-C fixtures measure scheduling,
  source coverage and call volume, not observation quality. No relevance
  percentages are claimed anywhere: expectations are deterministic counts
  and exact sets, not statistics.
- **Latency is overhead-shaped, not backend-shaped.** The fake server adds a
  simulated per-request delay; real network and real backend variance are
  not represented. The measured numbers bound the client-side pipeline
  (queries + guard read-backs + framing + accounting) under a controlled
  backend delay.

## 3. Named retrieval-relevance fixtures (QF-R, deterministic)

Each fixture is a named scenario in `test/t19-budgets-quality.test.ts` with
an EXPLICIT expected outcome asserted exactly (exact path sets, exact guard
steps, exact notes). Passing means the expectation held; there is no
tolerance band and no percentage.

| Fixture  | Scenario                                                           | Explicit expectation                                                                                                                        |
| -------- | ------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------- |
| QF-R1    | Positive recall: three active in-scope records matching the query  | Pack contains EXACTLY those three paths, highest FTS score first (`r1-a` → `r1-b` → `r1-c`); injection allowed with a defined token count.  |
| QF-R2    | Same text in an unauthorized scope (hybrid leg has no scope param) | Zero out-of-scope items; the candidate is guard-rejected at the `scope` step with a content-free note.                                      |
| QF-R3    | Superseded in-scope record still surfaced by search                | Zero superseded items; guard-rejected at the `status` step with a content-free note.                                                        |
| QF-R4    | Hybrid result attributed `keyword only`                            | Pack-wide degraded note (`hybrid search degraded: results lack full semantic attribution`); no hybrid item is counted as semantic evidence. |
| QF-R5    | Empty result set                                                   | Empty pack with the visible `no evidence passed the guard pipeline` note; nothing fabricated.                                               |
| QF-C1–C5 | Observation source coverage                                        | See §4.                                                                                                                                     |

These complement (and reuse the machinery of) the T19 chunk-1/2 fault-matrix
fixtures — B3 read-back rejection, brief-leg leakage, malformed SEARCH
output, dropped vector jobs — which remain the authoritative adversarial
set in `test/t19-fault-matrix.test.ts`.

## 4. Observation source coverage criteria (QF-C, deterministic)

The coverage contract for extraction is expressed as exact set equalities;
every criterion is asserted in the test file:

1. **QF-C1 full-batch coverage:** a threshold-triggered batch contains
   EVERY eligible unprocessed source entry; the outbox job's
   `sourceEntryIds` equal the batch's entry set, one batch, one model call.
2. **QF-C2 budget overflow never drops:** when entries exceed the 6,000-
   token input budget, the backlog splits into sequential batches whose
   union is the complete entry set and whose members are pairwise disjoint.
3. **QF-C3 queue-cap overflow never drops:** when pending batches exceed
   the cap, overflow merges into the oldest batch; at every point
   `durably-accepted ∪ durably-pending == all fed entries`, disjoint, and
   no entry is left unconsumed-and-unbatched.
4. **QF-C4 no duplicate work:** repeated settles over unchanged coverage
   schedule nothing and cost zero model calls (one call per unique source
   range).
5. **QF-C5 failure keeps coverage:** a failed extraction retains the SAME
   opId and the FULL entry set durably pending for re-derivation; nothing
   is accepted, consumed or duplicated by the failed attempt.

## 5. Reproducing

```
node --test test/t19-budgets-quality.test.ts   # regenerates tasks/evidence/t19-budget-report.json
```

Run within the full gate (`npm run check`) after any change to retrieval,
observation scheduling or budget configuration; the report is synthetic
local output and is safe to regenerate.
